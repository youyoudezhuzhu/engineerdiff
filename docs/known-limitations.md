# 已知限制

本文档记录 EngineerDiff 1.1.0 已确认的限制与边界，帮助用户正确理解比较结果。
"未支持"不代表以后不会支持；如对某项有需求，可通过项目 Issue 反馈。

---

## 1. 平台与分发

1. **仅支持 Windows 10/11（x64）**。未提供 32 位版本，也未提供原生 ARM64 构建
   （ARM64 Windows 可能通过 x64 仿真运行，但未做验证）。
2. **不提供 macOS/Linux 发行版**。Linux 仅用于打包配置的依赖收集自检，
   不作为交付产物，也不保证 Linux 下的 GUI/OCR 行为与 Windows 一致。
3. **安装包未做代码签名**：首次运行可能触发 Windows SmartScreen 提示，Windows 11
   智能应用控制（SAC）则会直接拦截未签名应用且不提供单应用放行；这并不代表文件含
   恶意代码。请用随包 `sha256sums.txt` 校验后按 `docs/code-signing.md` 处理，
   处理建议见 [Windows Defender 误报处理](windows-defender.md)。
4. **默认 per-user 安装**（`%LOCALAPPDATA%\Programs\EngineerDiff`）。经命令行
   `/ALLUSERS` 可改装到 Program Files，但需要管理员权限，此模式未作为默认真实验证路径。
5. **无自动更新/联网检查**：程序完全离线，不会检查新版本、不会上传任何数据。
6. **设置保存在当前用户注册表**：便携版也复用同一用户设置与 OCR 缓存，不是
   "把配置放在程序目录"的完全绿色版。
7. **UI 与安装包仅简体中文**：未提供英文或其他语言界面。

## 2. 文件格式与读取

### 2.1 支持范围

- 文本：仅 `.txt`。
- 表格：`.csv`、`.xls`、`.xlsx`。
- 图片：`.png`、`.jpg`、`.jpeg`、`.bmp`。
- **不支持**：PDF、Word（doc/docx）、`.xlsm`/`.xlsb`/`.ods`、`.tsv`、`.log`、
  注册表/二进制文件等。加密或受密码保护的 Office 文件会读取失败并提示。
- 两侧文件类型必须一致（文本↔文本、CSV↔CSV、Excel↔Excel、图片↔图片），
  不支持跨类型比较（如 TXT 与 XLSX）。

### 2.2 Excel

1. **严格按坐标比较**：同一行列位置的单元格才比较；默认不做智能行对齐。
   `smart_rows` 智能行对齐是**实验性**选项（默认关闭）：仅在**无合并单元格且不超过
   3000 行**时启用，否则自动回退严格坐标比较并给出 warning；开启后差异对齐方式可能
   变化，仍建议以严格模式结果为准。
2. **不比较样式**：字体、颜色、边框、数字格式等视觉样式不参与比较；仅比较
   值/公式/结构、合并区域、基本类型。样式还原也有限：**XLSX 主题色不还原**
   （仅还原 RGB / indexed 基础色）；数字格式只覆盖 General、固定小数位、千分位、
   百分比、科学计数、日期等常见格式，其他自定义格式可能显示为原始值或近似值。
3. **不比较以下对象**：批注、图表、图片、形状、数据透视表、条件格式、数据验证、
   宏、页眉页脚、打印设置、工作表保护/可见性状态。工作表**顺序**也不参与比较。
4. **工作表按名称精确配对**：工作表被重命名时会被识别为"仅左侧一个 + 仅右侧一个"，
   而不会识别为"同一工作表改名"。
5. **读取上限**：单表最多读取 50,000 行 × 2,000 列，且总单元格不超过 500,000；
   超出部分会被截断并给出中文提示（比较结果不包含截断区域）。
6. **XLS（旧格式）**：xlrd 无法读取公式表达式；即使选择
   `formula_mode=formula`（按公式表达式比较），实际也会退化为按缓存值比较，
   并给出中文 warning。
7. **XLSX 公式缓存值**：若文件从未在 Excel 中保存过计算结果，则缓存值可能缺失，
   按缓存值比较时会以**橙色**提示人工复核，不会当作相同。
8. **合并单元格**：合并区域不一致时只在合并锚点生成一条橙色提示，不展开到区域内部
   每个单元格。
9. **隐藏行/列/工作表**：会被读取并参与比较（不会自动跳过）；**隐藏行/列在表格
   视图中不会折叠，仍会显示**；隐藏状态本身不作为差异。
10. **数值精度**：数值按 Decimal 值比较（默认容差 0）。Excel 浮点表示可能造成
    看似相同的显示值存在极小差异；如业务允许，请设置数值容差。
11. **日期**：按规范化日期值比较；Excel 日期序列号与文本日期可能显示相同但被判为
    类型差异，这是有意设计（避免掩盖类型不一致）。

### 2.3 CSV

1. **不做类型推断**：所有非空字段按原始文本比较，因此 `001` 与 `1`、`1.50` 与 `1.5`
   会被判为不同；CSV 中没有"数值单元格"概念。
2. **分隔符识别是启发式的**：对单列文件、极少行、含大量引号的异常文件可能误判；
   左右分隔符不同时会提示，但无法自动统一列结构。
3. **表头不特殊处理**：表头行与普通行一样比较，不会按列名对齐。
4. **大文件**：解析与文本比较会将内容载入内存，超大 CSV 可能占用较多内存/较慢。
5. **文本视图**与表格视图基于同一文件：文本视图按原始文本逐行比较，可能受引号/
   字段内换行影响与表格视图结论不完全一致（这是两种视图的预期差异）。

### 2.4 文本

1. **编码识别是启发式的**：BOM → UTF-8 → GB18030/GBK → charset-normalizer → 兜底；
   极短或无中文的二进制样式文件可能识别错误，出现乱码时请转存为 UTF-8。
2. **按行比较**：不做段落/语义重排；长行会横向滚动。
3. **忽略选项会隐藏真实差异**：如"忽略全部空白/大小写"会按设置隐藏差异，
   默认全部关闭。
4. **不比较文件元数据**（修改时间、大小、权限），只看内容。

## 3. 图片 / OCR 比较

1. **文本驱动的差异，不做像素级比较**：只有 OCR 识别出的文字内容/存在性差异才会
   标红；仅靠颜色、线条、图标、布局位置变化而文字不变的改动**不会被检出**。
2. **文字移动但内容相同不报差异**：匹配算法会利用位置改善配对，但"同一文字换了位置"
   通常不视为差异。
3. **OCR 精度限制**：小字号（尤其低于约 10px 的截图）、低对比度、模糊、压缩失真、
   反色、倾斜/旋转、艺术字、手写体等情况识别率下降，可能产生误报或漏报。
   识别不可靠时会以**橙色**提示人工复核，而不会当作一致。
4. **模型语言范围**：内置 PP-OCRv4 中文 + 英文识别模型，其他语言/生僻字符
   支持有限，可能识别为乱码或错字。
5. **版面匹配限制**：算法针对"同一界面不同分辨率/窗口位置/缩放"的截图设计；
   若左右截图来自完全不同的窗口布局、字段顺序大幅变化或缩放差异极大，文字配对可能
   不可靠，会以橙色提示。
6. **重复文字歧义**：重复出现的字段（如多处"投入"、"0.00"）通过上下文与几何关系
   消歧；仍无法确定时会标橙并需人工在"OCR 校对"中指定对应关系。
7. **红框/橙框位置是估算的**：基于 OCR 四点框与 CJK/拉丁字符宽度比例估算字符级
   子框，高倍放大时可能与字形边缘有少量像素偏差；整框无法细化时退回整框高亮。
8. **首张图片慢**：首次 OCR 需加载模型（数秒）；之后相同图片命中缓存。大图
   （数千万像素以上）会增加内存与耗时。
9. **取消不是即时的**：OCR/推理调用本身不可中断，点击"取消"后会等当前推理返回再停止，
   期间界面可能短暂无响应。
10. **缓存基于图片内容哈希**：图片内容不变时复用结果；修改图片后自动重新识别。
    OCR 模型/算法版本变化时缓存自动失效。
11. **不支持**：截图自动滚动拼接、视频、扫描件自动纠偏、表格结构还原。
    批量图片比较可在“批量比较”页进行，每张图独立 OCR。

## 4. 界面与功能

1. **普通双栏模式一次只比较一对文件**；批量模式支持“一个基准 + 多个候选”的差异表，
   但不支持文件夹比较、多窗口并行、任意基准自动选择。
2. **只读查看**：不提供合并/编辑/保存文件、不生成差异报告文件、不支持打印/导出。
3. **无三方合并（3-way merge）**：仅双文件比较。
4. **无命令行非界面比较模式**：命令行仅用于 `--self-test`（安装包自检）与
   `--left/--right` 预填文件；不提供类似 `diff` 的纯命令行输出。
5. **剪贴板粘贴限制**：支持粘贴图片与文件路径；**不支持**把复制的纯文本内容直接
   当作一侧文件比较（可先保存为 txt 再粘贴文件）。
6. **同步是近似的**：滚动同步按滚动条比例/数值同步，行高、缩放或版面不同可能
   存在对齐误差；Excel 工作表同步仅在开启"同步滚动"时生效。
7. **"仅显示差异"的上下文**：表格视图仅显示差异行及少量上下文行；文本视图会隐藏
   相同行，可能与原文件行号视觉上不连续。表格视图的**列标/行号表头不随 zoom 缩放**
   （缩放只作用于单元格内容），放大时表头相对变小便于固定定位。
8. **高 DPI/多显示器**：支持 Qt 高 DPI，但跨不同 DPI 显示器移动窗口时，图片缩放与
   覆盖层可能需要重新适应窗口；覆盖框坐标始终基于原图像素，不受影响。
9. **设置生效时机**：多数比较设置在下一次比较/重新比较时生效；"同步滚动""仅显示差异"
   等视图开关立即生效。
10. **关闭窗口时会等待后台比较/OCR 安全结束**（最长可能到当前推理完成），期间窗口
    可能短暂无响应。

### 4.1 Fluent 界面边界

1. **Mica/Acrylic**：当前 PySide6 窗口使用实色 Fluent 表面与原生标题栏，没有强行开启
   Mica/Acrylic 透明材质；这是为了不牺牲 Excel 矩阵和 OCR 原图的清晰度，属于设计取舍。
2. **批量矩阵**：Excel 按基准 Sheet 分组并支持折叠；位置列与 Sheet 组标题固定，但候选列
   横向滚动时不会冻结前两列（Qt 标准表头行为）。
3. **图片原图对照**：一次显示基准 + 一个候选，通过下拉切换候选；不是所有候选同时铺满一屏。
4. **批量页的文件导入区**：比较完成后自动收缩为紧凑区域，仍可继续添加/移除文件。

## 5. 性能与资源

1. Excel/CSV 读取与比较在后台线程执行，但仍是单线程；超大文件耗时较长。
2. 图片 OCR 为 CPU 推理（未使用 GPU），分辨率越高越慢；高分辨率截图建议先裁剪到
   关注区域。
3. 安装包约数百 MB（Qt + ONNX Runtime + OCR 模型），便携版解压后占用相近。
4. OCR 缓存会占用用户磁盘，可在设置中清除。

## 6. 打包、测试与可验证性

1. **真实 Windows 构建以 GitHub Actions `windows-latest` 为准**：仓库内
   `scripts/build_linux_check.sh` 仅验证 PyInstaller 依赖收集（模型/Qt/动态库是否
   进入 dist），Linux 产物**不交付**，也不能代表 Windows 运行结果。
2. **安装包实测由 CI 覆盖**：静默安装 → 安装目录断言（OCR 模型、Qt 插件、VC++ 运行库、
   文档/许可证）→ 安装后 `--self-test`（断言退出码、`ok=true`、`frozen=true`）→
   静默卸载并断言目录移除。该流程验证的是 CI 环境，不覆盖所有 Windows 版本/组策略环境。
3. **`--self-test` 覆盖引擎与模型，不覆盖完整 GUI 交互**：它检查文本/CSV/Excel 比较、
   OCR 模型、图片比较流程、界面组件导入等；真实鼠标操作、渲染效果由 offscreen 截图与
   人工验证补充。
4. **自动化测试不等同于全部真实场景**：测试使用合成数据与生成截图，真实工程文件
   （复杂公式、加密、特殊样式、极端截图）建议抽样人工复核关键差异。
5. **可复现性**：`requirements.txt` 锁定关键版本，但部分传递依赖使用版本区间；
   不同时间构建的安装包字节可能不同，功能一致性以测试与自检为准。

## 7. 许可证与合规相关限制

1. PySide6/Qt 以 LGPL-3.0 动态链接分发，用户可替换安装目录中的 Qt 库；替换后兼容性
   由用户自行负责。
2. 随包 VC++ 运行库 DLL 属于 Microsoft 再分发组件，不在 MIT 许可范围内；
   安装包附带的第三方许可证清单见 `THIRD-PARTY-NOTICES.md` 与 `LICENSES/`。
3. OCR 模型来自 RapidOCR/PaddleOCR（Apache-2.0），模型精度/效果由上游决定，
   本软件不做精度承诺。

## 8. 批量比较

1. **一个基准 + 多个候选**：批量比较以列表第一个文件为基准；不支持“任意基准自动选择”。
2. **按基准位置汇总**：文本按基准行号、表格按基准单元格坐标、图片按基准文字框位置合并
   差异。候选文件“仅新增”的行/单元格/文字框会作为单独行出现；多个候选各自新增的
   不同内容不会自动合并为同一行。基准中不存在的位置也会按“（不存在）”展示。
3. **类型必须一致**：同一批只能全部是 TXT、全部 CSV、全部 Excel 或全部图片；混合类型会
   直接拒绝。
4. **图片批量较慢**：每张图片都需要 OCR；完全相同的图片会跳过 OCR，重复比较会命中缓存。
5. **批量表不替代双栏原图**：批量表给出位置和各文件值，红色表示任意文件不同；需要查看
   原始内容上的字符/单元格/截图覆盖框时，请用该对文件打开普通双栏比较。

## 9. Windows 安全提示 / Smart App Control

本项目未附带代码签名证书，PyInstaller exe 与 Inno Setup 安装包可能被 Microsoft Defender
的启发式规则误报。**根治办法是使用受信任的代码签名证书重新签名**；项目提供
[Windows Defender 误报处理](windows-defender.md) 与可选签名脚本 `scripts/sign_release.ps1`。


## 10. 代码签名 / 智能应用控制

1. 当前 GitHub Release 的安装包与便携 exe **未使用代码签名证书**。Windows 11 智能应用控制
   （Smart App Control）会阻止未签名或签名无效的应用，且**没有单应用白名单/放行入口**。
2. 1.0.1 与 1.0.2 的正式 exe 经检查都未签名、PE 结构一致；1.0.2 只是新增批量模块导致
   哈希变化，不是本次功能改动引入的安全问题。SAC 可能因新哈希尚无云端信誉而拦截。
3. 唯一适合分发的解决方式是使用受信任的代码签名证书/ Microsoft Trusted Signing 签名
   `EngineerDiff.exe` 与安装包；否则只能在测试机关闭 SAC 或使用未启用 SAC 的环境。
4. 详见 `docs/code-signing.md` 与 Microsoft Smart App Control FAQ。
